---
title: "Аутентификация"
description: "Аутентифицируйте запросы к каждому API PapelShip с помощью своего API-ключа."
---

Каждый запрос должен содержать API-ключ. Разные API принимают немного разные наборы заголовков.

<Tabs>
  <Tab title="User API">
    Передавайте API-ключ **и** хеш магазина в каждом запросе.

    ```bash
    x-api-key: your_api_key
    x-store-hash: your_store_hash
    ```

    | Заголовок | Описание |
    | :-- | :-- |
    | `x-api-key` | Ваш личный API-ключ из настроек панели управления. |
    | `x-store-hash` | Уникальный идентификатор вашего магазина. |
  </Tab>
  <Tab title="qPapel Protection">
    Передавайте ключ разработчика (`pk_live_...`) одним из трех способов.

    ```bash
    # Предпочтительный
    Authorization: Bearer pk_live_your_key
    
    # Альтернативный
    x-api-key: pk_live_your_key
    
    # Устаревший (поддерживается для старых загрузчиков)
    api-key: pk_live_your_key
    ```
  </Tab>
</Tabs>

## Проверьте учетные данные

Вызовите эндпоинт проверки подключения User API, чтобы убедиться, что ключ и хеш магазина работают:

```bash
curl https://app.papelship.com/api/v1/me \
  -H "x-api-key: your_api_key" \
  -H "x-store-hash: your_store_hash"
```

Корректный запрос возвращает `"success": true`. Неверный ключ возвращает `401 Unauthorized`.

## Храните ключи в безопасности

<AccordionGroup>
  <Accordion title="Используйте ключи только на сервере" icon="server">
    API-ключи дают полный доступ к вашему магазину и лицензиям. Никогда не встраивайте их во фронтенд-код JavaScript, мобильные приложения или распространяемые десктопные сборки.
  </Accordion>

  <Accordion title="Храните ключи в переменных окружения" icon="lock">
    Загружайте ключи из переменных окружения или менеджера секретов. Никогда не добавляйте их в систему контроля версий.
  </Accordion>

  <Accordion title="Немедленно замените утекший ключ" icon="rotate">
    Если ключ оказался раскрыт, отзовите его в панели управления и создайте новый.
  </Accordion>
</AccordionGroup>
