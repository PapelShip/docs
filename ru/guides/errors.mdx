PapelShip использует стандартные коды состояния HTTP. Каждый JSON-ответ содержит логическое поле `success`.

```json Ответ с ошибкой
{
  "success": false,
  "error": "Invalid parameters provided"
}
```

## Коды состояния

| Код | Значение | Что делать |
| :-- | :-- | :-- |
| `200` | Запрос выполнен успешно. | Прочитайте тело ответа. |
| `400` | Некорректный запрос или ошибка валидации. | Проверьте обязательные поля и типы значений. |
| `401` | API-ключ отсутствует или недействителен. | Проверьте заголовки аутентификации. |
| `403` | У ключа нет разрешения на это действие. | Используйте ключ с нужной областью доступа. |
| `404` | Ресурс не найден. | Проверьте ID в URL или в запросе. |
| `500` | Ошибка сервера. | Повторите запрос с экспоненциальной задержкой. |

## Ошибки Store API

Ошибки Store API также содержат машиночитаемый `code`, необязательное поле `details` и `request_id`, который можно сообщить в поддержку:

```json Ошибка Store API
{
  "success": false,
  "code": "PRODUCT_NOT_FOUND",
  "error": "Product a1B2c3D4e5F6 not found in this store",
  "details": { "field": "items[0].product_id" },
  "request_id": "req_8fK2mQ1xZ7pL0vN3"
}
```

Опирайтесь на `code`, а не на текст сообщения. Все коды описаны в разделе [Ошибки Store API](/ru/user-api/errors).

<Tip>
  Повторяйте запросы только при сетевых сбоях и ответах `5xx`. При каждом повторе передавайте тот же `Idempotency-Key`. См. [Идемпотентность](/ru/guides/idempotency).
</Tip>
