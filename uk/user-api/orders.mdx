Замовлення (рахунок) містить товари, клієнта та ціну. Клієнт оплачує на хостинговій сторінці `checkout_url`, де обирає будь-який спосіб оплати, який приймає ваш магазин.

Замовлення, створені через API, підпорядковуються тим самим правилам, що й ваша вітрина: ціни беруться з вашого каталогу, залишки резервуються, застосовуються купони та правила товарів, виконуються перевірки на шахрайство.

## Створіть замовлення

Перенаправте клієнта на `checkout_url`. Неоплачені замовлення спливають через 3 години.

    | Поле | Примітки |
    | :-- | :-- |
    | `customer_email` | Обов'язкове. Отримує лист із рахунком і доставку. |
    | `items` | Обов'язкове. Від 1 до 50 рядків із `product_id` (хеш-ID), `quantity` і `variant_id` для товарів із варіантами. |
    | `coupon_code` | Застосовується, якщо дійсний для цих товарів. |
    | `customer_ip` | IP покупця. Вмикає для цього замовлення ваші правила щодо шахрайства, VPN і чорного списку. |
    | `expected_total_cents` | Необов'язкова перевірка. Виклик завершується помилкою `TOTAL_MISMATCH`, якщо ціна змінилася. |
    | `shipping_address`, `shipping_rate_id` | Фізичні товари. Див. нижче. |
    | `custom_fields` | Відповіді на поля вашої сторінки оформлення. |
    | `affiliate_code` | Зараховує замовлення партнеру вашої партнерської програми. |
    | `send_email` | `false`, щоб не надсилати лист із рахунком (за замовчуванням `true`). |
    | `metadata` | До 20 ваших власних рядкових пар ключ/значення. |

## Фізичні товари

Для товарів, які потребують доставки, додайте адресу. Спершу отримайте варіанти через `POST /shipping/quote` або не вказуйте `shipping_rate_id`, щоб застосувати найдешевший тариф.

```json
{
  "customer_email": "buyer@example.com",
  "items": [{ "product_id": "Tsh1rtM3d1um", "variant_id": 2041, "quantity": 2 }],
  "shipping_address": {
    "full_name": "Alex Morgan",
    "phone": "+44 20 7946 0958",
    "country_code": "GB",
    "city": "London",
    "line1": "221B Baker Street",
    "postal_code": "NW1 6XE"
  },
  "shipping_rate_id": 12
}
```

Вартість доставки додається до `total_cents` і показується як `shipping_cents`. Без адреси клієнт вводить її на сторінці оформлення перед оплатою. Після оплати відправте замовлення через [`POST /orders/{invoiceId}/shipments`](/uk/user-api/fulfillment).

## Статуси замовлень

| Статус | Значення |
| :-- | :-- |
| `pending` | Очікує оплати від клієнта. |
| `payment_pending`, `payment_processing` | Клієнт обрав спосіб оплати; платіж обробляється. |
| `partial_payment` | Надійшла частина суми (криптовалюта). |
| `manual_review_pending` | Ручний платіж очікує вашої перевірки. |
| `completed` | Оплачено й доставлено. |
| `cancelled` | Скасовано до оплати. |
| `expired` | Не оплачено вчасно. |

Замість регулярного опитування слухайте вебхук `order.completed`. Див. [Вебхуки](/uk/user-api/webhooks).

## Після створення замовлення

| Дія | Ендпоінт | Коли |
| :-- | :-- | :-- |
| Позначити як оплачене | `POST /invoices/{id}/complete` | Ви отримали гроші поза PapelShip (банківський переказ, готівка). Доставляє товари. |
| Скасувати | `POST /invoices/{id}/cancel` | Замовлення не оплачене. Звільняє зарезервовані залишки. |
| Зафіксувати повернення коштів | `POST /invoices/{id}/refund` | Ви повернули кошти клієнту. Надішліть `amount_cents` для часткового повернення. |
| Переглянути доставлене | `GET /invoices/{id}/deliveries` | Ліцензійні ключі, файли та нотатки, надіслані клієнту. |
| Оновити | `PATCH /invoices/{id}` | Змінити `metadata` або `delivery_email`. |

<Tip>
  Використовуйте ID власного замовлення як `Idempotency-Key` для викликів створення, завершення та повернення коштів. Тоді повторні спроби ніколи не створять друге замовлення чи друге повернення.
</Tip>
