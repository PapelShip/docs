Мережеві збої трапляються. Коли запит завершується тайм-аутом, ви не можете знати, чи створив PapelShip замовлення. Заголовок `Idempotency-Key` дає змогу безпечно повторити виклик Store API.

## Як це працює

Додайте заголовок `Idempotency-Key` (до 255 символів) до запиту на створення або дію. PapelShip зберігає першу відповідь протягом 24 годин. Повторний запит із тим самим ключем і тим самим тілом отримує збережену відповідь, а не виконується знову.

```bash
curl -X POST https://app.papelship.com/api/v1/invoices \
  -H "x-api-key: pk_live_your_key" \
  -H "x-store-hash: your_store_id" \
  -H "Idempotency-Key: 9a8b7c6d-5e4f-3a2b-1c0d-9e8f7a6b5c4d" \
  -H "Content-Type: application/json" \
  -d '{ "customer_email": "buyer@example.com", "items": [{ "product_id": "a1B2c3D4e5F6" }] }'
```

| Код | Статус | Значення |
| :-- | :-- | :-- |
| `IDEMPOTENCY_IN_PROGRESS` | `409` | Перший запит із цим ключем ще виконується. Повторіть спробу трохи пізніше. |
| `IDEMPOTENCY_KEY_REUSED` | `422` | Ключ уже використано з іншим тілом. Для іншого запиту використовуйте новий ключ. |

## Ендпоінти, які його приймають

Ключ працює на ендпоінтах створення та дій Store API, зокрема:

- `POST /invoices` (створення замовлення)
- `POST /invoices/{invoiceId}/papelpay` (запуск оплати карткою)
- `POST /invoices/{invoiceId}/complete` і `POST /invoices/{invoiceId}/refund`
- `POST /orders/{invoiceId}/shipments`
- `POST /products` і `POST /coupons`

## Рекомендації

- Генеруйте один ключ на замовлення, а не на запит. Добре підходить ID вашого власного замовлення.
- Зберігайте ключ разом із замовленням, щоб кожна повторна спроба використовувала його знову.
- Ніколи не використовуйте ключ повторно для іншого замовлення чи іншої суми.
