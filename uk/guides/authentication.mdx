---
title: "Автентифікація"
description: "Автентифікуйте запити до кожного API PapelShip за допомогою свого API-ключа."
---

Кожен запит має містити API-ключ. Кожен API приймає дещо інший набір заголовків.

<Tabs>
  <Tab title="User API">
    Надсилайте свій API-ключ **і** хеш магазину в кожному запиті.

    ```bash
    x-api-key: your_api_key
    x-store-hash: your_store_hash
    ```

    | Заголовок | Опис |
    | :-- | :-- |
    | `x-api-key` | Ваш персональний API-ключ із налаштувань панелі керування. |
    | `x-store-hash` | Унікальний ідентифікатор вашого магазину. |
  </Tab>
  <Tab title="qPapel Protection">
    Надсилайте свій ключ розробника (`pk_live_...`) одним із трьох способів.

    ```bash
    # Рекомендовано
    Authorization: Bearer pk_live_your_key
    
    # Альтернатива
    x-api-key: pk_live_your_key
    
    # Застарілий спосіб (підтримується для старих завантажувачів)
    api-key: pk_live_your_key
    ```
  </Tab>
</Tabs>

## Перевірте свої облікові дані

Викличте ендпоінт перевірки з'єднання User API, щоб переконатися, що ваш ключ і хеш магазину працюють:

```bash
curl https://app.papelship.com/api/v1/me \
  -H "x-api-key: your_api_key" \
  -H "x-store-hash: your_store_hash"
```

Коректний запит повертає `"success": true`. Недійсний ключ повертає `401 Unauthorized`.

## Бережіть свої ключі

<AccordionGroup>
  <Accordion title="Використовуйте ключі лише на сервері" icon="server">
    API-ключі надають повний доступ до вашого магазину та ліцензій. Ніколи не вбудовуйте їх у фронтенд-JavaScript, мобільні застосунки чи поширювані десктопні бінарні файли.
  </Accordion>

  <Accordion title="Зберігайте ключі у змінних середовища" icon="lock">
    Завантажуйте ключі зі змінних середовища або менеджера секретів. Ніколи не додавайте їх до системи контролю версій.
  </Accordion>

  <Accordion title="Негайно замінюйте скомпрометований ключ" icon="rotate">
    Якщо ключ став відомим стороннім, відкличте його в панелі керування та створіть новий.
  </Accordion>
</AccordionGroup>
