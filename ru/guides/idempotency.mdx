Сетевые сбои случаются. Если запрос завершился по тайм-ауту, вы не можете знать, создал ли PapelShip заказ. Заголовок `Idempotency-Key` позволяет безопасно повторить вызов Store API.

## Как это работает

Добавьте заголовок `Idempotency-Key` (до 255 символов) к запросу на создание или действие. PapelShip хранит первый ответ 24 часа. Повторный запрос с тем же ключом и тем же телом получает сохраненный ответ, а не выполняется заново.

```bash
curl -X POST https://app.papelship.com/api/v1/invoices \
  -H "x-api-key: pk_live_your_key" \
  -H "x-store-hash: your_store_id" \
  -H "Idempotency-Key: 9a8b7c6d-5e4f-3a2b-1c0d-9e8f7a6b5c4d" \
  -H "Content-Type: application/json" \
  -d '{ "customer_email": "buyer@example.com", "items": [{ "product_id": "a1B2c3D4e5F6" }] }'
```

| Код | Статус | Значение |
| :-- | :-- | :-- |
| `IDEMPOTENCY_IN_PROGRESS` | `409` | Первый запрос с этим ключом еще выполняется. Повторите чуть позже. |
| `IDEMPOTENCY_KEY_REUSED` | `422` | Ключ уже использовался с другим телом запроса. Для другого запроса используйте новый ключ. |

## Эндпоинты, которые его принимают

Ключ работает на эндпоинтах Store API для создания и действий, в том числе:

- `POST /invoices` (создать заказ)
- `POST /invoices/{invoiceId}/papelpay` (начать оплату картой)
- `POST /invoices/{invoiceId}/complete` и `POST /invoices/{invoiceId}/refund`
- `POST /orders/{invoiceId}/shipments`
- `POST /products` и `POST /coupons`

## Рекомендации

- Генерируйте один ключ на заказ, а не на запрос. Хорошо подходит ID вашего собственного заказа.
- Храните ключ вместе с заказом, чтобы каждый повтор использовал его снова.
- Никогда не используйте один ключ для другого заказа или другой суммы.
