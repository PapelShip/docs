PapelShip використовує стандартні HTTP-коди стану. Кожна JSON-відповідь містить логічне поле `success`.

```json Відповідь з помилкою
{
  "success": false,
  "error": "Invalid parameters provided"
}
```

## Коди стану

| Код | Значення | Що робити |
| :-- | :-- | :-- |
| `200` | Запит виконано успішно. | Прочитайте тіло відповіді. |
| `400` | Некоректний запит або помилка валідації. | Перевірте обов'язкові поля та типи значень. |
| `401` | API-ключ відсутній або недійсний. | Перевірте заголовки автентифікації. |
| `403` | Ключ не має дозволу на цю дію. | Використайте ключ із потрібною областю доступу. |
| `404` | Ресурс не знайдено. | Перевірте ID в URL або в параметрах запиту. |
| `500` | Помилка сервера. | Повторіть запит з експоненційною затримкою. |

## Помилки Store API

Помилки Store API також містять машиночитний `code`, необов'язкові `details` і `request_id`, який слід указати у зверненні до підтримки:

```json Помилка Store API
{
  "success": false,
  "code": "PRODUCT_NOT_FOUND",
  "error": "Product a1B2c3D4e5F6 not found in this store",
  "details": { "field": "items[0].product_id" },
  "request_id": "req_8fK2mQ1xZ7pL0vN3"
}
```

Розгалужуйте логіку за `code`, а не за текстом повідомлення. Усі коди наведено в розділі [Помилки Store API](/uk/user-api/errors).

<Tip>
  Повторюйте запити лише в разі мережевих збоїв і відповідей `5xx`. Надсилайте той самий `Idempotency-Key` під час кожної повторної спроби. Див. [Ідемпотентність](/uk/guides/idempotency).
</Tip>
